# ExpenseHub — Personal Expense Tracker API

**A production-oriented backend project built with Python, FastAPI, PostgreSQL, and SQLAlchemy.**

ExpenseHub is a personal finance and expense-tracking backend designed to demonstrate practical backend engineering skills, including REST API development, database management, schema migrations, input validation, testing, security, containerization, and deployment.

The project follows a **modular monolith architecture**: functionality is organized into clear modules within one application, keeping development manageable while allowing the system to grow.

## Implemented API Endpoints

Base URL: `http://127.0.0.1:8000`

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/expenses/` | Create an expense |
| GET | `/expenses/` | Retrieve expenses |
| PUT | `/expenses/{expense_id}` | Replace an expense's editable fields |
| PATCH | `/expenses/{expense_id}` | Partially update an expense |
| DELETE | `/expenses/{expense_id}` | Delete an expense |

### Example: Create an Expense

**Request**

```json
{
  "title": "Metro Ticket",
  "amount": "61.00",
  "category": "Travel"
}
```

**Expected successful response:** `201 Created`

```json
{
  "id": 1,
  "title": "Metro Ticket",
  "amount": "61.00",
  "category": "Travel",
  "created_at": "2026-10-21T00:00:00"
}
```

The ID and timestamp are generated by the database. The timestamp above is illustrative.

## Getting Started

### Prerequisites

Install the following:

- Python 3.12
- Docker Desktop
- Git

### 1. Clone the repository

```bash
git clone <your-github-repository-url>
cd expense_tracker
```

### 2. Create and activate a virtual environment

On Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 4. Configure environment variables

Create a local `.env` file in the project root:

```env
DATABASE_URL=postgresql+psycopg://root:<your-password>@localhost:5433/expense_tracker
```

Replace `<your-password>` with the password configured for your PostgreSQL container. Never commit actual credentials to GitHub.

The example assumes the Docker PostgreSQL service is exposed on host port `5433`. Adjust it if your local configuration differs.

### 5. Start PostgreSQL

If your existing Docker Compose configuration defines the database service, start it from the project root:

```powershell
docker compose up -d
```

Check the running containers:

```powershell
docker compose ps
```

### 6. Apply database migrations

```powershell
python -m alembic upgrade head
```

To check the current migration revision:

```powershell
python -m alembic current
```

### 7. Start FastAPI

```powershell
uvicorn app.main:app --reload
```

Open `http://127.0.0.1:8000/docs` to try the endpoints.

## Database Design

The initial Expense model contains:

| Field | Purpose |
|---|---|
| `id` | Primary key |
| `title` | Expense description |
| `amount` | Monetary amount using a decimal-compatible database type |
| `category` | Expense category |
| `created_at` | Database-generated creation timestamp |

SQLAlchemy defines the model, while Alembic tracks schema changes through versioned migrations.

## Engineering Principles

ExpenseHub is being developed with the following principles:

- Keep API routes, database models, schemas, and business logic separated.
- Validate all incoming data.
- Use decimal-compatible types for financial values.
- Manage database schema changes through migrations.
- Use explicit transactions and appropriate error handling.
- Add authentication and ownership checks before supporting multiple users.
- Write automated tests before introducing more complex features.
- Introduce infrastructure tools only when they solve a real problem.
